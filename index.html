افزونهٔ کروم — قفل طلایی (GoldLock)

1Overview

GoldLock is a Chrome extension designed to protect normal web browsing with a user-defined password.

This Privacy Policy explains what information GoldLock stores, how it is used, and what information is not collected or transmitted.

۱مرور کلی

قفل طلایی افزونه‌ای برای کروم است که با گذرواژه‌ای که کاربر تعیین می‌کند، از مرور عادی وب محافظت می‌کند.

این سیاست حریم خصوصی توضیح می‌دهد قفل طلایی چه اطلاعاتی را ذخیره می‌کند، چگونه از آن‌ها استفاده می‌شود و چه اطلاعاتی جمع‌آوری یا منتقل نمی‌شوند.

2Data Storage

GoldLock stores extension settings locally in Chrome storage. chrome.storage.local may contain setup status, password-verification data, Recovery Key-verification data, the selected interface language, and preferences such as History Lock and Extension Protection.

Password and Recovery Key verification records contain cryptographic hashes and salts, not the plain-text secrets. Temporary lock-session state and the destination URLs of blocked tabs may be kept in chrome.storage.session so GoldLock can restore navigation after authentication. This session state is not intended to be a permanent browsing-history database.

۲ذخیره‌سازی داده‌ها

قفل طلایی تنظیمات افزونه را به‌صورت محلی در حافظهٔ کروم ذخیره می‌کند. chrome.storage.local ممکن است وضعیت راه‌اندازی، داده‌های تأیید گذرواژه و کلید بازیابی، زبان رابط کاربری و ترجیح‌هایی مانند قفل سابقهٔ مرور و محافظت افزونه را نگه دارد.

رکوردهای تأیید گذرواژه و کلید بازیابی شامل هش رمزنگاری‌شده و نمک هستند، نه خود رمز یا کلید به‌صورت متن ساده. وضعیت موقت قفل و نشانی مقصدِ زبانه‌های مسدودشده ممکن است در chrome.storage.session نگه‌داری شود تا پس از احراز هویت، پیمایش به مقصد بازگردد. این دادهٔ نشست برای ساخت پایگاه دائمی سابقهٔ مرور در نظر گرفته نشده است.

3Browsing and Navigation Data

GoldLock uses Chrome's tabs and webNavigation APIs to check tab destinations and enforce its browser-lock feature. When the lock is active, GoldLock checks navigation to normal HTTP and HTTPS websites and can redirect protected tabs to its own setup or lock screen. If a destination is blocked, GoldLock temporarily stores that destination in chrome.storage.session so it can return the tab to the original destination after successful authentication. This temporary entry is removed when it is no longer needed or when the tab closes.

The History Lock feature protects Chrome's chrome://history page when enabled. The Extension Protection feature can also redirect Chrome's chrome://extensions page to the GoldLock lock screen when enabled.

Important: GoldLock does not create or upload a browsing-history database. In its current implementation, it does not read webpage text, form contents, or cookies. It does not transmit browsing destinations, passwords, or Recovery Keys to GoldLock servers. Navigation information is processed locally only to enforce the lock and restore the destination after authentication.

۳داده‌های مرور و پیمایش

قفل طلایی از APIهای tabs و webNavigation کروم برای بررسی مقصد زبانه‌ها و اجرای قابلیت قفل مرورگر استفاده می‌کند. هنگامی که قفل فعال است، قفل طلایی پیمایش به وب‌سایت‌های معمولی HTTP و HTTPS را بررسی می‌کند و می‌تواند زبانه‌های تحت محافظت را به صفحهٔ راه‌اندازی یا قفل خود هدایت کند. اگر مقصدی مسدود شود، قفل طلایی آن مقصد را موقتاً در chrome.storage.session ذخیره می‌کند تا پس از احراز هویت موفق، زبانه را به مقصد اولیه بازگرداند. این دادهٔ موقت پس از پایان نیاز یا بسته‌شدن زبانه حذف می‌شود.

قابلیت قفل سابقهٔ مرور، در صورت فعال بودن، از صفحهٔ chrome://history کروم محافظت می‌کند. قابلیت محافظت افزونه نیز در صورت فعال بودن می‌تواند صفحهٔ chrome://extensions کروم را به صفحهٔ قفل قفل طلایی هدایت کند.

مهم: قفل طلایی پایگاه داده‌ای از سابقهٔ مرور ایجاد یا بارگذاری نمی‌کند. در پیاده‌سازی فعلی، متن صفحات وب، محتوای فرم‌ها یا کوکی‌ها را نمی‌خواند. نشانی مقصدهای مرور، گذرواژه‌ها یا کلیدهای بازیابی را به سرورهای قفل طلایی ارسال نمی‌کند. اطلاعات پیمایش فقط برای اجرای قفل و بازگرداندن مقصد پس از احراز هویت، به‌صورت محلی پردازش می‌شود.

4Accounts and Online Recovery

GoldLock does not require a user account, email address, or online recovery service. Recovery is designed to work offline using the user's Recovery Key.

The Recovery Key is generated locally. Its plain-text value is shown to the user when generated and is not persisted by GoldLock as plain text.

۴حساب کاربری و بازیابی آنلاین

قفل طلایی به حساب کاربری، نشانی ایمیل یا سرویس بازیابی آنلاین نیاز ندارد. بازیابی به‌گونه‌ای طراحی شده است که به‌صورت آفلاین و با کلید بازیابی کاربر انجام شود.

کلید بازیابی به‌صورت محلی ساخته می‌شود. هنگام ساخت، مقدار آن به‌شکل متن ساده به کاربر نمایش داده می‌شود، اما قفل طلایی آن را به‌صورت متن ساده ذخیره نمی‌کند.

5Third-Party Services

GoldLock does not use third-party analytics, advertising, tracking, or remote recovery services.

GoldLock uses browsing-related information only to provide its disclosed browser-lock features, including checking navigation destinations, redirecting protected tabs while locked, and restoring destinations after successful authentication. This information is processed locally and is not sold, used for advertising or profiling, or shared with third parties. Its use is limited to the functionality described in this policy.

۵خدمات اشخاص ثالث

قفل طلایی از خدمات تحلیل‌گر، تبلیغات، ردیابی یا بازیابی از راه دورِ اشخاص ثالث استفاده نمی‌کند.

قفل طلایی از اطلاعات مرتبط با مرور فقط برای ارائهٔ قابلیت‌های اعلام‌شدهٔ قفل مرورگر استفاده می‌کند؛ از جمله بررسی مقصدهای پیمایش، هدایت زبانه‌های تحت محافظت هنگام قفل بودن و بازگرداندن مقصدها پس از احراز هویت موفق. این اطلاعات به‌صورت محلی پردازش می‌شوند، فروخته نمی‌شوند، برای تبلیغات یا پروفایل‌سازی مورد استفاده قرار نمی‌گیرند و با اشخاص ثالث به اشتراک گذاشته نمی‌شوند. استفاده از این اطلاعات به قابلیت‌هایی که در این سیاست توضیح داده شده‌اند محدود است.

6Remote Code

GoldLock does not download or execute remote JavaScript or other remotely hosted executable code.

۶کد از راه دور

قفل طلایی جاوااسکریپت یا کد اجرایی دیگری را از راه دور دانلود یا اجرا نمی‌کند.

7Permissions and Managed Protection

GoldLock requests the Chrome API permissions storage, tabs, webNavigation, and management. It also declares host permissions for all HTTP and HTTPS websites using the patterns http://*/* and https://*/*. These permissions support GoldLock's browser-locking and protection features.

  • storage: Stores extension settings locally, including password and Recovery Key verification records, language preferences, and protection settings. Temporary lock-session state and blocked-tab destinations are stored in Chrome session storage.
  • tabs: Lets GoldLock check the URLs of browser tabs and redirect protected tabs to its lock or setup screen when required by the lock state and settings.
  • webNavigation: Lets GoldLock respond to main-frame navigation events and redirect protected navigation so a blocked destination does not remain open while the lock is active.
  • management: Lets the settings page read Chrome's reported information about GoldLock itself, including its installation type and whether Chrome allows it to be disabled. GoldLock uses this information to display the status of managed protection; it does not use this permission to manage or disable other extensions.
  • Host permissions: The declared host patterns cover all HTTP and HTTPS websites, rather than a user-selected list of individual sites. This access supports applying GoldLock's browser-wide lock to normal websites. In the current implementation, these permissions support navigation protection; GoldLock does not inject scripts into webpages or use them to collect webpage content.

The History Lock feature can protect Chrome's history page, and the Extension Protection feature can redirect Chrome's extension-management page when that setting is enabled.

Managed Protection status is read-only. GoldLock does not create, modify, or remove Chrome enterprise policies. Force-install protection must be configured outside the extension by a device or organization administrator.

۷مجوزها و محافظت مدیریت‌شده

قفل طلایی مجوزهای API کروم شامل storage، tabs، webNavigation و management را درخواست می‌کند. همچنین دسترسی میزبانی برای تمام وب‌سایت‌های HTTP و HTTPS را با الگوهای http://*/* و https://*/* در مانیفست تعریف کرده است. این مجوزها برای اجرای قابلیت‌های قفل مرورگر و محافظت قفل طلایی استفاده می‌شوند.

  • storage: تنظیمات افزونه را به‌صورت محلی ذخیره می‌کند؛ از جمله رکوردهای تأیید گذرواژه و کلید بازیابی، زبان رابط کاربری و تنظیمات محافظت. وضعیت موقت نشست قفل و مقصد زبانه‌های مسدودشده نیز در حافظهٔ نشست کروم ذخیره می‌شود.
  • tabs: به قفل طلایی اجازه می‌دهد نشانی زبانه‌های مرورگر را بررسی کند و در صورت لزوم، با توجه به وضعیت قفل و تنظیمات، زبانه‌های تحت محافظت را به صفحهٔ قفل یا راه‌اندازی هدایت کند.
  • webNavigation: به قفل طلایی اجازه می‌دهد به رویدادهای پیمایش صفحهٔ اصلی واکنش نشان دهد و پیمایش‌های تحت محافظت را هدایت کند تا مقصد مسدودشده در حالت قفل باز نماند.
  • management: به صفحهٔ تنظیمات اجازه می‌دهد اطلاعاتی را که کروم دربارهٔ خود افزونهٔ قفل طلایی گزارش می‌کند بخواند؛ از جمله نوع نصب و اینکه آیا کروم اجازهٔ غیرفعال‌کردن افزونه را می‌دهد یا نه. این اطلاعات برای نمایش وضعیت محافظت مدیریت‌شده استفاده می‌شوند؛ قفل طلایی از این مجوز برای مدیریت یا غیرفعال‌کردن افزونه‌های دیگر استفاده نمی‌کند.
  • دسترسی میزبانی: الگوهای تعریف‌شده، تمام وب‌سایت‌های HTTP و HTTPS را پوشش می‌دهند و به فهرستی از سایت‌های انتخاب‌شده توسط کاربر محدود نیستند. این دسترسی برای اعمال قفل سراسری قفل طلایی روی وب‌سایت‌های معمولی لازم است. در پیاده‌سازی فعلی، این مجوزها برای محافظت از پیمایش استفاده می‌شوند؛ قفل طلایی اسکریپتی را به صفحات وب تزریق نمی‌کند و از این دسترسی برای جمع‌آوری محتوای صفحات استفاده نمی‌کند.

قابلیت قفل سابقهٔ مرور می‌تواند از صفحهٔ سابقهٔ کروم محافظت کند و قابلیت محافظت افزونه نیز در صورت فعال‌شدن می‌تواند صفحهٔ مدیریت افزونه‌های کروم را هدایت کند.

وضعیت محافظت مدیریت‌شده فقط خواندنی است. قفل طلایی سیاست‌های سازمانی کروم را ایجاد، تغییر یا حذف نمی‌کند. نصب اجباری باید خارج از افزونه و توسط مدیر دستگاه یا سازمان پیکربندی شود.

8Security

GoldLock verifies passwords and Recovery Keys using PBKDF2 with SHA-256, 150,000 iterations, and a random salt. A Recovery Key is generated locally using the browser's cryptographically secure random-number generator. Verification hashes and salts stay in the Chrome profile rather than being transmitted to a remote service. These measures help protect stored verification data but cannot guarantee absolute security; the security of the device and Chrome profile also matters.

۸امنیت

قفل طلایی گذرواژه و کلید بازیابی را با الگوریتم PBKDF2 همراه با SHA-256، تعداد ۱۵۰٬۰۰۰ تکرار و نمک تصادفی اعتبارسنجی می‌کند. کلید بازیابی نیز به‌صورت محلی و با مولد اعداد تصادفی رمزنگارانهٔ مرورگر ساخته می‌شود. هش‌ها و نمک‌های تأیید در نمایهٔ کروم باقی می‌مانند و به سرویس راه دور ارسال نمی‌شوند. این روش‌ها به محافظت از داده‌های تأیید ذخیره‌شده کمک می‌کنند، اما امنیت مطلق را تضمین نمی‌کنند؛ امنیت خود دستگاه و نمایهٔ کروم نیز اهمیت دارد.
